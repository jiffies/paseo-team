# 普通检查的简洁输出

仅在 Developer 需要运行输出冗长的格式化、lint、单元测试或 CI 时使用 [run-check.mjs](../scripts/run-check.mjs)。它不调用模型，不改变模型和 Profile，也不代替业务验收。

先检查目标程序不会输出凭据。工具为子进程设置 `SKIP_DOTENV=true` 与空 dotenv 路径，但不能约束忽略这些约定的程序；必要的测试变量使用非秘密占位值。不要用于真实 API、认证集成或网络验证，也不自动改写其他命令。

从待测项目目录运行，日志目录需已存在，建议使用候选外的稳定任务证据目录：

```bash
node /path/to/paseo-team/scripts/run-check.mjs \
  --log /path/to/task-evidence/ci-1.log -- npm run ci
```

`--` 后按独立参数传递程序与参数，不经 shell 展开；管道、重定向等不是隐式支持的语法。需要多步检查时优先调用项目已有 npm script。工具不读取或复制 `.env`，不打印命令参数或环境。它不审查任意目标程序，不授予运行该程序的权限。

- 成功：只输出 `PASS`、原退出码及完整日志路径，不把成功日志带入模型上下文。
- 失败：输出 `FAIL`、原退出码、signal、日志路径、最多 2000 字符的末尾输出和 `truncated`。末尾摘录不是错误根因分析，也可能未包含真正错误；需要时按日志位置补读相关内容。
- 启动或日志处理异常：输出 `ERROR` 且工具非零退出，不把异常当作检查通过。命令无法启动时 `exitCode` 为 null。
- 工具保留命令的非零退出码；signal 终止映射为 `128 + 信号编号`，另保留 signal。证据不只看摘要文字，需同时核对工具退出状态；日志处理失败可能使原本成功的命令也被视为工具失败。
- stdout/stderr 全部写入同一新日志，不按关键词过滤原始内容。已有文件和符号链接均拒绝覆盖；重跑使用新日志名。

交付索引记录实际检查命令、候选和日志路径。成功日志也可按需查看，不能因为输出简短就忽略项目要求的检查或警告。已有可靠 CI 摘要时直接复用，无需额外包装或重复执行。
