# Paseo Team

当前对话主持，配置中的一个 Developer 实现。主控可以是 Claude、Codex 或其他受支持的模型；不为启动团队另开主控。以完成原始需求为目标，在必要质量约束下减少总耗时与费用。

## 0. 先分流命令与任务

Claude 使用 `/paseo-team`，Codex 使用 `$paseo-team`。这是一套 Skill 约定，不是 Paseo CLI 的新子命令。

本入口供主控编排。被派出的 Developer、Reviewer 或方案成员只执行交接中的角色任务，不因材料提到本 Skill 就重新选人、加载整套编排说明或启动团队；仅在角色任务需要时读取相应参考。项目和宿主要求的指令仍须遵守。

- `setup`：读取真实 Profiles，一次询问成员别名、各主控默认开发者及两/三人审查组，再保存。只配置，不启动团队。
- `status`：显示全局配置、当前主控默认及缺失项；任务已启动时优先报告其冻结名单。
- `preset save 名称 --dev 别名 --audit 名单`：保存一个可选常用组合，不改变默认简单模式。
- 普通任务：可加 `--dev 别名`、`--preset 名称`；`--audit 0/2/3/名单` 控制方案和交付两个阶段，`--plan` 或 `--review` 只控制相应阶段。`--audit` 不与后两者混用。

读取 [配置与选人](references/configuration.md)，使用随 Skill 安装的 [团队工具](scripts/team.mjs) 解析、保存和冻结名单。根据当前主会话的可信运行身份自动传 `--lead claude` 或 `--lead codex` 等，不要求新对话重复输入；身份无法确定时一次询问，不能用 Developer 身份或默认模型名称猜测。

配置为同一主机/用户共用的 `~/.config/paseo-team/config.json`，按主控分别取默认，不按会话分别配置。优先级：本次参数 → 所选 preset → 当前主控默认 → 通用默认；显式 `null` 表示未设置，不能回退。没有审查参数或含审查的 preset，始终不审查。自然语言“审查一下”按交付两人审查理解；“完整对抗性审查”对应 `--audit 2`，用户指定阶段/人数/成员时遵从。只分析请求不因选了审查而派开发者。

普通实现任务启动时，将目标与参数分开处理，在候选外的稳定任务目录写入不可覆盖的 `team.json`。它冻结成员、Profile ID、provider、model、mode、thinking 与 features；后续阶段读取快照，不随其他对话的 setup 或 Profile 修改换人。未配置时可按现有 Developer/Codex、Architect/Claude、QA/Codex 生成兼容草案，Codex 主控审查组保持未设置。缺失/不兼容时明确报告，不自行创建 Profile、换模型或减少人数。

## 1. 默认简单合作，审查须明确同意

先读实际项目，整理目标、约束、非目标和简短可验证的验收条件。区分用户必需行为与自行提出的增强，不把演示任务扩展为全面重构、精密仿真或完整生产系统。

未明确要求或同意审查时，一律采用简单模式，不要求用户先选模式，也不因复杂度或风险自动升级：

| 情况                                                                              | 工作流                                                                                                |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 未明确要求或同意审查                                                              | **简单合作（默认）**：当前主控方案 → 单 Developer 实现及必要验证 → 主控核对回执后返回；不创建审查会话 |
| 复杂方案、关键假设不明、反复修复失败，或涉及资金、权限、迁移、并发/恢复等实质风险 | 可以简短说明审查的作用与额外耗时、成本，询问是否启用；收到明确同意前保持简单模式                      |
| 用户明确要求或同意对抗性审查                                                      | **按选择执行审查**：方案和交付分别由冻结名单的全部成员独立审查；只选一个阶段就只执行该阶段            |
| 仅分析或等待必要的需求决定                                                        | 提供方案与证据，到授权边界结束，不派实现                                                              |

审查建议尽量一次提出，不反复追问；已要求审查的不再重复确认，已拒绝或明确“不要 review”的继续简单模式。未回复不代表同意，不预先创建委员会、Reviewer 或用“独立验证”变相增加审查者。等待审查选择时可继续已授权且不依赖该答复的工作；若缺少的是必要需求或操作授权，则暂停对应步骤并说明实际问题。

只有用户明确要求或同意后才读取 [审查流程](references/review.md) 并启动相应角色。仅要求交付 review/双审，不自动增加方案委员会；仅要求方案委员会，不自动增加交付双审。简单模式仍须必要验证，准确说明“未做独立审查”，不绕过权限或掩盖关键未知，也不为缺少 QA Profile 停下。

仅分析任务输出方案与证据后结束，跳过实施交接、候选检查和合并章节。

## 2. 按需读取官方能力与 Profiles

读取本机官方 `paseo` 的必要用法及本次所需 Profiles/notes。需要实现时再读 `paseo-handoff`，用户已同意相应审查时再读 `paseo-committee`、`paseo-advisor`，运行异常再读 `paseo-help`。同一会话不重复加载未变的全文，不复制上游协议。

| 职责                  | 现有 Profile                 | 边界                                             |
| --------------------- | ---------------------------- | ------------------------------------------------ |
| 当前主持者            | 当前主会话，无需另建 Profile | 澄清、方案、调度、决策；不写业务代码、不运行测试 |
| 实现与验证            | 所选别名的 developer Profile | 候选唯一写入者；实现、测试、记录及 Git 写操作    |
| 按需方案成员/Reviewer | 所选别名的 reviewer Profiles | 全新会话，独立只读分析；不递归启动团队           |

按冻结名单应用完整 Profile 设置，**不为省钱或提速擅自降档、换模型或修改 Provider 设置**。用户通过 setup、preset 或本次参数选择其他模型是有效指令。以 Profile ID 绑定，不因改名失效；新模型能否使用取决于 Paseo 已配置的 Provider/模型能力，添加别名不能创建这种能力。

边界按角色划分，不按模型品牌划分。主控可通过工具管理团队配置与任务记录，不写业务实现；Developer 可为 Codex、DeepSeek 等，但始终一个写入者，不再拆成多个并行开发 Agent。只读 Advisor/committee 不运行会写文件的测试；需要动态证据时交 Developer。仅在用户要求独立验证，或已同意的审查中确需独立动态证据时，才另派有能力的独立验证会话，不让它改正式候选。

## 3. 一次交接，减少往返

核对当前 Workspace、目录、分支和用户改动。已有隔离 worktree 就复用；缺少时使用 Paseo 官方能力建立。不要让 `using-git-worktrees` 重建已有隔离，也不要求用户填写 worktree setup scripts 才能开工。当前主会话留在原位置，不假称已经移动。

通过官方 handoff 将原始业务目标、短方案、必需验收、非目标、实际路径、基线 M、验证要求及交付终点交给 Developer。交接去掉 `/paseo-team`、`$paseo-team` 调用前缀和已解析的选人参数，把角色与审查范围单独写明；原调用留在主控任务记录。不得借此删减用户约束或把主控解释冒充原始要求。

只给成员完成本角色需要的材料：Developer 收到实现与验证要求；审查者收到原始目标、候选、证据入口和审查提示。复杂任务另附方案 P 与决策位置。完整团队配置和选人过程由主控维护，不要求成员重读 setup、整份冻结名单或本 Skill 全文；交接明确“只执行本角色，不重新编排团队”。

派出后立即返回成员信息，等完成通知继续，不轮询催促。准备信息能一次读齐就批量读；没有依赖的检查并行，候选修改、冻结、审查和合并保持先后顺序。不同任务分别使用自己的 worktree；同一候选只保留一个写入者。

Developer 根据项目已有工具运行格式化、lint、CI 和与需求相关的验证。没有配置就说明，不为凑检查数量新建工具链。记录失败与未验证项，不能弱化断言换通过；风险相符时做真实入口、关键行为或视觉验证。

完成后固定候选 C；源码、索引、交付文件都对应 C。小任务通常用一份 `delivery.json` 索引集中记录 task_id、M/C、cwd、完成行为、检查命令/退出码、原始证据位置和未验证项，再附必要测试日志及浏览器证据。现成 CI 报告或可追溯的官方工具活动可直接引用；不为每条命令、时间戳或角色另造一份 JSON，也不强制新的报告格式。

验证结果必须对应 C。若验证发生在提交前，用受测源码哈希等证据确认提交后内容未变；批量核对，通常只输出匹配摘要或差异，不反复展开全部哈希。版本匹配不能代替行为验证，审查者仍须独立读取相关代码和原始结果。

截图优先复用工具返回的文件或附件路径；需持久化时直接复制或导出到稳定证据目录。工具仅返回编码图像时优先程序化保存，避免让模型反复转述、拆分长 Base64 或为同一结论重复截图。纯证据放在候选外按任务隔离，不能只留会被清理的 `/tmp`；本应交付的测试和文档仍进入候选。

只返回候选时核对任务 worktree，不要求 main 干净或仍停留在 M，也不执行合并检查。准备本地合并时再读取 [工具用法](references/tools.md)，使用随 Skill 安装的 [工作流工具](scripts/workflow.mjs) 批量检查，不重新编写相同脚本。

## 4. 回报短，事实可追溯

成员回报优先给：**状态、候选 C、完成的必需行为、检查结果、阻断/未验证项、证据路径**。正常通过时简短说明检查范围和关键依据，不逐文件复述源码、日志或哈希；约 1500 字符是通常上限，不是目标长度。复杂发现可按需展开，不为限字删掉阻断或未知。引用文件行号应先用带行号的读取或搜索核实。完整报告由会话记录保留，可按成员 ID 读取；只读 Reviewer 不为存报告自行写文件。

通知出现截断、缺结论或缺版本时，通过官方活动读取能力补取必要全文，不能凭完成状态或截断摘要放行。主控直接核对结果与原始目标及版本，处理实质分歧；不重新复述所有完整报告，也不再当额外的全量 Reviewer。

简单模式的回执、必要验证与实际状态吻合后即可返回；不要求先升级双审。仅在用户明确要求或同意审查后，按 [审查流程](references/review.md) 执行，不一边修改候选一边审查。

## 5. 交付终点与合并

默认做到候选完成后返回。用户要求“实现后返回”就保留候选；只有用户已经授权本地合并时才推进 main。轻量任务不因要合入而自动变成双审；按所选模式验收，准确记录是否独立审查。

合并由 Developer 使用 [工作流工具](scripts/workflow.mjs)，在共同锁内检查基线、候选、相关工作树状态，再只快进到固定 C。开发、测试和审查不持锁；锁忙就返回等待状态，main 已变就回任务 worktree 更新、验证，原本需要 review 的任务重新确认新候选。

新流程使用 Git common directory 下的 `main-publish.lock`；存在旧 `herdr-main-publish.lock` 时工具自动兼容，不依赖 Herdr，不改名或删除旧锁。所有本流程合并者都走同一入口；仓库另有发布协议时复用它。仅发现锁文件不等于确认其他写入者遵守协议，不能以此声称全仓并发安全；未协调的写入者应先串行安排。工具不可用时说明原因，不即兴绕过检查或新增常驻调度器。

禁止覆盖、reset 或 stash 用户改动。未经授权不 push、部署、交易、detach、归档或删除 worktree。禁止读取、搜索内容、打印或上传 `.env` 和其他秘密，不输出环境变量全集。普通检查隔离真实凭据；已授权真实 API 验证仅允许已检查无泄密日志的可信目标程序内部加载配置。

## 6. 结束与效率

结果只需说明完成行为、必要验证、候选、审查是否执行、未验证项和是否合并。轻量任务不要求额外生成一份长篇验收文档。

能从运行记录直接取得时，附总耗时、主要阶段耗时、累计 token/缓存量、修复轮次；有已知价格和计费渠道再估算费用。模型不同，token 占比不能冒充费用占比；并行成员耗时不能相加当任务耗时。不要为每个小任务另派审计 Agent、扫描全机日志或调用收费模型来统计成本。

减少重复全文读取、长篇转述、无效检查与不必要的串行往返；达到必需验收后停止。用同类任务的耗时、费用及交付后返工比较优化效果，不虚报节省比例，也不因时间或预算耗尽把未完成事项宣布通过。
