# Paseo Team

当前 Claude 主持，Codex 实现。以完成原始需求为目标，在必要质量约束下减少总耗时与费用；不把更多 Agent、更多测试或更长报告当成更好的交付。

## 1. 默认简单合作，审查须明确同意

先读实际项目，整理目标、约束、非目标和简短可验证的验收条件。区分用户必需行为与自行提出的增强，不把演示任务扩展为全面重构、精密仿真或完整生产系统。

未明确要求或同意审查时，一律采用简单模式，不要求用户先选模式，也不因复杂度或风险自动升级：

| 情况                                                                              | 工作流                                                                                                    |
| --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 未明确要求或同意审查                                                              | **简单合作（默认）**：Claude 方案 → Codex 实现及必要验证 → Claude 核对回执后返回；不创建委员会或 Reviewer |
| 复杂方案、关键假设不明、反复修复失败，或涉及资金、权限、迁移、并发/恢复等实质风险 | 可以简短说明审查的作用与额外耗时、成本，询问是否启用；收到明确同意前保持简单模式                          |
| 用户明确要求或同意对抗性审查                                                      | **对抗性审查模式**：复杂方案先开委员会，交付由独立 Claude 与 Codex 双审；用户限定审查范围时遵从           |
| 仅分析或等待必要的需求决定                                                        | 提供方案与证据，到授权边界结束，不派实现                                                                  |

审查建议尽量一次提出，不反复追问；已要求审查的不再重复确认，已拒绝或明确“不要 review”的继续简单模式。未回复不代表同意，不预先创建委员会、Reviewer 或用“独立验证”变相增加审查者。等待审查选择时可继续已授权且不依赖该答复的工作；若缺少的是必要需求或操作授权，则暂停对应步骤并说明实际问题。

只有用户明确要求或同意后才读取 [审查流程](references/review.md) 并启动相应角色。仅要求交付 review/双审，不自动增加方案委员会；仅要求方案委员会，不自动增加交付双审。简单模式仍须必要验证，准确说明“未做独立审查”，不绕过权限或掩盖关键未知，也不为缺少 QA Profile 停下。

仅分析任务输出方案与证据后结束，跳过实施交接、候选检查和合并章节。

## 2. 按需读取官方能力与 Profiles

读取本机官方 `paseo` 的必要用法及本次所需 Profiles/notes。需要实现时再读 `paseo-handoff`，用户已同意相应审查时再读 `paseo-committee`、`paseo-advisor`，运行异常再读 `paseo-help`。同一会话不重复加载未变的全文，不复制上游协议。

| 职责                  | 现有 Profile                         | 边界                                          |
| --------------------- | ------------------------------------ | --------------------------------------------- |
| 当前主持者            | Architect / Claude                   | 澄清、方案、调度、决策；不写代码、不运行测试  |
| 实现与验证            | Developer / Codex                    | 候选唯一写入者；实现、测试、记录及 Git 写操作 |
| 按需方案成员/Reviewer | 新 Architect / Claude、新 QA / Codex | 独立只读分析；不递归启动团队                  |

保持当前模型、思考档位、Claude Auto、Codex Full Access 等完整配置，**不为省钱或提速降档、换模型或修改全局设置**。名称变化时按 notes/provider 核对等价配置；只检查本次所需角色，缺失时报告，不静默替换或创建。

所有 Claude 不写业务、测试、配置、脚本，不运行安装、构建、格式化、服务或浏览器验证。只读 Advisor/committee 不运行会写文件的测试；需要动态证据时交 Developer。仅在用户要求独立验证，或已同意的审查中确需独立动态证据时，才另派 QA/Codex 验证任务。

## 3. 一次交接，减少往返

核对当前 Workspace、目录、分支和用户改动。已有隔离 worktree 就复用；缺少时使用 Paseo 官方能力建立。不要让 `using-git-worktrees` 重建已有隔离，也不要求用户填写 worktree setup scripts 才能开工。当前主会话留在原位置，不假称已经移动。

通过官方 handoff 将原始目标、短方案、必需验收、非目标、实际路径、基线 M、验证要求及交付终点交给 Developer。复杂任务另附方案版本 P 和决策记录位置；不把整个团队 Skill 转发给成员。

派出后立即返回成员信息，等完成通知继续，不轮询催促。准备信息能一次读齐就批量读；没有依赖的检查并行，候选修改、冻结、审查和合并保持先后顺序。不同任务分别使用自己的 worktree；同一候选只保留一个写入者。

Developer 根据项目已有工具运行格式化、lint、CI 和与需求相关的验证。没有配置就说明，不为凑检查数量新建工具链。记录失败与未验证项，不能弱化断言换通过；风险相符时做真实入口、关键行为或视觉验证。

完成后固定候选 C；源码、索引、交付文件都对应 C。结果绑定 M/C、命令、cwd、退出码和必要原始证据位置，有现成测试报告就直接引用。只返回候选时核对任务 worktree，不要求 main 干净或仍停留在 M，也不执行合并检查。准备本地合并时再读取 [工具用法](references/tools.md)，使用随 Skill 安装的 [工作流工具](scripts/workflow.mjs) 批量检查，不重新编写相同脚本。

纯证据放在候选外的稳定位置，例如用户状态目录下按仓库和任务隔离的目录；保留候选、命令和证据索引。临时浏览器或构建文件可以在 `/tmp`，但不要把唯一交付证据留在可能清理的临时目录。不得因此遗漏本应交付的测试或文档。

## 4. 回报短，事实可追溯

成员回报优先给：**状态、候选 C、完成的必需行为、检查结果、阻断/未验证项、证据路径**。默认控制在约 1500 字符内；复杂发现可按需展开，不为限字删掉阻断或未知。完整报告由会话记录保留，可按成员 ID 读取；只读 Reviewer 不为存报告自行写文件。

通知出现截断、缺结论或缺版本时，通过官方活动读取能力补取必要全文，不能凭完成状态或截断摘要放行。主控直接核对结果与原始目标及版本，处理实质分歧；不重新复述两份完整报告，也不再当第三个全量 Reviewer。

简单模式的回执、必要验证与实际状态吻合后即可返回；不要求先升级双审。仅在用户明确要求或同意审查后，按 [审查流程](references/review.md) 执行，不一边修改候选一边审查。

## 5. 交付终点与合并

默认做到候选完成后返回。用户要求“实现后返回”就保留候选；只有用户已经授权本地合并时才推进 main。轻量任务不因要合入而自动变成双审；按所选模式验收，准确记录是否独立审查。

合并由 Developer 使用 [工作流工具](scripts/workflow.mjs)，在共同锁内检查基线、候选、相关工作树状态，再只快进到固定 C。开发、测试和审查不持锁；锁忙就返回等待状态，main 已变就回任务 worktree 更新、验证，原本需要 review 的任务重新确认新候选。

新流程使用 Git common directory 下的 `main-publish.lock`；存在旧 `herdr-main-publish.lock` 时工具自动兼容，不依赖 Herdr，不改名或删除旧锁。所有本流程合并者都走同一入口；仓库另有发布协议时复用它。仅发现锁文件不等于确认其他写入者遵守协议，不能以此声称全仓并发安全；未协调的写入者应先串行安排。工具不可用时说明原因，不即兴绕过检查或新增常驻调度器。

禁止覆盖、reset 或 stash 用户改动。未经授权不 push、部署、交易、detach、归档或删除 worktree。禁止读取、搜索内容、打印或上传 `.env` 和其他秘密，不输出环境变量全集。普通检查隔离真实凭据；已授权真实 API 验证仅允许已检查无泄密日志的可信目标程序内部加载配置。

## 6. 结束与效率

结果只需说明完成行为、必要验证、候选、审查是否执行、未验证项和是否合并。轻量任务不要求额外生成一份长篇验收文档。

能从运行记录直接取得时，附总耗时、主要阶段耗时、累计 token/缓存量、修复轮次；有已知价格和计费渠道再估算费用。模型不同，token 占比不能冒充费用占比；并行成员耗时不能相加当任务耗时。不要为每个小任务另派审计 Agent、扫描全机日志或调用收费模型来统计成本。

减少重复全文读取、长篇转述、无效检查与不必要的串行往返；达到必需验收后停止。用同类任务的耗时、费用及交付后返工比较优化效果，不虚报节省比例，也不因时间或预算耗尽把未完成事项宣布通过。
