# 验证说明

结构检查、工具测试、行为模拟和真实 Paseo 联动是不同证据，不能互相替代。

## 自动检查

| 检查                               | 能证明                                                                 | 不能证明                                |
| ---------------------------------- | ---------------------------------------------------------------------- | --------------------------------------- |
| Prettier、Markdown lint、Node 语法 | 显式列出的源文件格式及基本语法有效                                     | 模型会正确选择流程                      |
| Skill 校验器                       | Claude frontmatter、本地引用、模板残留检查                             | 审查有效或 Agent 真正独立               |
| Git 工具集成测试                   | 固定候选快进，拒绝脏工作树、旧基线、错误候选，锁互斥和兼容，合并后检查 | 外部写入者遵守共同锁、真实项目验收通过  |
| GitHub Actions                     | Node.js 22/24 可重复运行检查                                           | 已安装个人 Skill、已跑真实多 Agent 流程 |

检查只读取明确的公开源文件，不扫描配置或秘密，不加载 `.env`，不调用模型服务。Git 测试在临时仓库使用独立配置和虚构身份，不接触真实仓库或凭据。

本 Skill 面向 Claude Code，有意保留 `argument-hint`、`disable-model-invocation`。仅接受 Codex 元数据字段的通用校验器可能拒绝这两个字段；不能为了通过它而移除 Claude 的入口设置，以项目的 Claude 元数据检查为准。

## 行为评估

用真实请求和必要原始材料检查实际决策，不以关键词匹配代替行为评估。评估不必为每次文案修改启动新团队；复杂路由变化时可做一次隔离模拟，不创建真实 Paseo Agent、不修改业务仓库或推送。

| 场景                                   | 核对行为                                                       |
| -------------------------------------- | -------------------------------------------------------------- |
| 简单文案修改，只有 Architect/Developer | 轻量协作、必要验证后返回，不要求 QA 或新增审查                 |
| 普通动画，明确不要 review              | 不召开交付双审，不扩大到精密仿真，准确报告未独立审查           |
| 用户要求交付双审                       | 并行新建两个 Reviewer，对同一候选独立判断，不自动增加委员会    |
| 根因不明的跨模块重构，未指定模式       | 默认简单模式，可说明理由并询问审查，不自动创建委员会           |
| 资金或权限变化，用户尚未回复审查建议   | 不把沉默当同意，不启动审查者，可继续已授权且不依赖答复的工作   |
| 用户同意完整对抗性模式                 | 复杂方案先开委员会，交付由独立 Claude 与 Codex 双审            |
| 用户只要求方案委员会                   | 只做方案审查，不自动增加交付双审                               |
| 用户拒绝审查建议或明确不要 review      | 继续简单合作、必要验证，准确报告未审查，不反复追问             |
| 完成通知被截断                         | 补读成员报告，不能凭完成状态或不完整摘要放行                   |
| 一方批准后候选改变                     | 旧批准失效，同会话增量复审并分别确认新候选                     |
| main 前进或锁忙                        | 不覆盖、不轮询、不持锁等验证；更新基线后重新验证，按原模式审查 |
| 用户只要返回候选，main 有用户改动      | 不自动合入，不因 main 状态执行合并检查或阻止返回               |
| 想节省成本                             | 减少重复工作，不更换模型、降低思考档位或修改 Profiles          |
| 仅分析                                 | 不派写入实现，不编造测试或批准                                 |

模拟结果应说明评估者和工具。一次 Codex 模拟不能称为真实 Claude + Codex 双审；阅读官方源码也不能称为运行过委员会。

## 真实联动

在已授权的测试仓库运行两种代表任务：未指定模式的简单合作和用户明确同意独立审查的任务。记录当前源码版本、所需 Profiles、工作目录、候选、成员、完成通知和实际结果。

轻量路径应只有当前 Claude 和 Developer：派出即返回，完成通知续接，必要验证有证据，准确说明未做独立审查，不自动合并或创建 QA。

审查路径必须有用户明确要求或同意的依据，然后才创建独立新会话：首轮不交换结论，回到真实代码和证据，变更后增量复审，双方批准同一新候选。完整对抗性模式中按复杂度启用委员会；仅要求交付双审时不能自动追加委员会，也不能因存在 Reviewer 就声称方案已审。

已经授权本地合并时，确认工作流工具的锁与所有自动发布入口一致，状态变化应阻止合并；不以锁文件存在当作协议已经落实。

优化效果应比较同类任务的总耗时、阶段耗时、按模型价格估算费用、修复轮次和交付后返工，不预先承诺固定节省比例。保留关键原始证据，但不记录凭据、授权头或敏感 URL。
