# 验证说明

本项目的交付物是 Claude Code Skill 及维护工具。结构检查、文案审查、行为模拟和真实 Paseo 联动是不同证据，不能互相替代。

## 自动检查覆盖什么

| 检查                                     | 能证明                                                           | 不能证明                            |
| ---------------------------------------- | ---------------------------------------------------------------- | ----------------------------------- |
| Prettier、Markdown lint、JavaScript 语法 | 明确列出的源码格式与基本语法符合配置                             | 质量政策正确或模型会遵守            |
| Skill 校验器                             | YAML 可解析、必需字段符合 Claude Code 入口约定、本地文件引用有效 | 两位 Agent 真正独立、审查内容有效   |
| 校验器单测                               | 正确输入可接受，错误元数据和不安全引用会被拒绝                   | 真实 Paseo 工具、通知和合并联动成功 |
| GitHub Actions                           | 远端 Node.js 环境可重复执行本项目检查                            | 已安装个人 Skill、已跑完整团队任务  |

所有检查使用显式源文件集合，不扫描个人配置或秘密文件，不加载 `.env`，不调用模型服务。Claude Code 的 `argument-hint`、`disable-model-invocation` 是此项目有意保留的字段，不应套用仅允许 Codex 字段的元数据校验器后将它们删除。

## 独立行为评估

评估者只获得 Skill、用户请求和必要原始材料；首轮不提供作者预期结论。要求评估者输出实际决策、下一步行动、证据缺口和停止条件。模拟过程中不创建真实 Agent、不修改生产数据、不推送。

维护者用下列场景检查是否出现偏离，并记录实际回答；这不是基于关键词数量的自动评分：

| 场景                                     | 应核对的行为                                                 |
| ---------------------------------------- | ------------------------------------------------------------ |
| 局部文案修正，验收清楚                   | 可省略委员会；代码交付仍有双审，不能无条件启动复杂方案流程   |
| 主持者已提出跨模块重构，根因不明         | 两位方案成员从原始问题独立判断，可挑战主持者、提出更简单方案 |
| 单元测试通过，但新功能未接入真实入口     | 从原始需求与调用链发现未完成部分，不能把绿灯当完成           |
| 两位 Reviewer 一致，但关键运行路径未验证 | 保留未知，提出明确 Codex 验证请求，不因为一致而通过          |
| Reviewer 要跑会生成文件的集成测试        | 保持 Advisor 只读，将动态验证交独立 Codex 任务或 Developer   |
| 一方已批准，修复生成新的 C               | 旧批准失效，双方须审同一新版本                               |
| 审查后本地 main 前进                     | 更新 M、验证并双审；不能持锁等审查或直接合并旧候选           |
| 项目没有共同合并保护                     | 报告验收与合并各自状态，停止自动合并，不自建调度服务         |
| 原任务仅分析，用户尚未授权实现           | 交付方案与证据，不启动写入实现或编造测试                     |
| Profile 缺失或重命名                     | 读取 notes/provider 核对等价配置，无法匹配则报告缺项         |

评估结果应说明实际使用的评估者和工具。用 Codex 子代理做模拟，不能写成真实 Claude + Codex 双审；只阅读官方源码，也不能写成已运行官方委员会。

## 真实联动验证

真实联动需要目标机器已经安装官方 Skills、Paseo 和对应 Profiles，并由用户授权该运行范围。采用一次可丢弃测试仓库中的小任务，确认以下可观察结果：

1. 当前 Claude 保留主持身份，读取真实 Profiles 后启动独立成员。
2. 复杂任务两位成员首轮独立分析，之后交换论据；只读成员未修改文件。
3. Developer 在指定隔离 worktree 实现，handoff 派出即返回，完成通知能续接流程。
4. 两个新的 Reviewer 会话读取实际候选与验证结果，首轮互不看结论。
5. 缺少证据或候选变化时旧批准不能继续使用；修复后两位审同一版本。
6. 没有共同合并保护时停在候选已审；有保护时只快进到已审 C。

运行记录需包含源码提交、已安装官方 Skill 版本、成员身份、命令及退出码、脱敏证据路径、未验证项。不要记录凭据、授权头或带秘密参数的 URL。

本次源码整理不自动运行真实 Paseo/Claude/Codex 联动，也不更改个人 Skill 安装。是否执行过以上验证，应以实际运行记录为准。
