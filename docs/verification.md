# 验证说明

结构检查、工具测试、行为演练和真实 Paseo 联动是不同证据，不能互相替代。

## 自动检查

| 检查                               | 能证明                                                         | 不能证明                                 |
| ---------------------------------- | -------------------------------------------------------------- | ---------------------------------------- |
| Prettier、Markdown lint、Node 语法 | 公开源文件格式及基本语法有效                                   | 模型会正确调度                           |
| Skill 校验器                       | Claude frontmatter、Codex 显式调用设置、本地引用有效           | 审查有效或会话真正独立                   |
| 团队配置测试                       | 按主控取默认、参数优先级、人数与成员检查、保存冲突、快照不漂移 | 真实 Provider 可运行、Agent 遵守读写边界 |
| Git 工具集成测试                   | 固定候选快进、拒绝状态变化、锁互斥与旧锁兼容                   | 外部写入者遵守同一协议、业务验收通过     |
| GitHub Actions                     | 在 Node.js 22/24 上重复执行检查                                | 已安装个人 Skill、已跑多模型联动         |

检查只读取明确的公开源文件，不扫描秘密，不加载 `.env`，不调用模型。配置测试只操作临时目录；Git 测试使用临时仓库、独立配置和虚构身份。完整 Git 测试需要 Linux/WSL 的 `flock` 与符号链接能力；Windows 上相关用例失败不能当作完整 CI 通过。

保留 Claude 的 `argument-hint`、`disable-model-invocation`，Codex 另使用 `agents/openai.yaml`。旧的通用 Skill 校验器可能不接受 Claude 扩展字段；不能为了通过它移除入口设置，以项目的联合元数据检查为准。

## 需覆盖的行为

| 场景                                   | 应有结果                                                   |
| -------------------------------------- | ---------------------------------------------------------- |
| Claude、Codex 各开新对话               | 自动读各自主控默认，不再逐次要求用户选人                   |
| 简单任务，无审查参数                   | 一个开发者，必要验证后返回，不要求 QA                      |
| Codex 未设置两人组                     | 简单任务可运行；请求两人审查时提示缺口，不退回 Claude      |
| setup 或 preset save                   | 仅修改配置，不启动团队                                     |
| 新增模型别名                           | 映射真实 Profile，无需改 Skill；能力不可用时不假装支持     |
| `--review 2`                           | 两个新交付会话，不增设方案审查                             |
| `--audit 3`                            | 三个方案会话和三个全新交付会话；不把同阶段会话用于另一阶段 |
| 本次 `--review` 覆盖含 audit 的 preset | 仅做交付审查                                               |
| 用户明确不要 review                    | 不因高风险自动启用；必要授权缺失仍暂停相应操作             |
| 另一个对话保存 setup                   | 已冻结任务仍按原名单、模型和档位执行                       |
| 并发配置修改                           | revision 与短锁阻止静默覆盖                                |
| 多人首轮观点相同                       | 有证据可停止，不强行制造争论                               |
| Reviewer 的计算或前提错误              | 其他成员以原始证据纠正，不因身份或多数票接受               |
| 仅某阶段通过                           | 不扩大为全部上线完成、真实交易成功或额外保证               |
| 候选变化                               | 全部所选成员增量复审并明确批准新候选                       |
| main 前进或锁忙                        | 不覆盖、不持锁等待验证；更新后按原模式重新确认             |
| 只要求返回候选，main 有用户改动        | 不自动合并，也不以 main 状态阻止返回                       |
| 仅分析任务                             | 不要求开发者，不派写入实现，不进入合并流程                 |

还应观察成员交接是否保留原始业务需求和约束、是否避免重新编排团队；小任务能否通过一份索引定位版本、命令和原始结果；已有截图文件是否直接复用；评审能否核实引用后简短回报，单纯勘误不重复未受影响的检查。

这些是行为验收场景，不能用关键词匹配代替实际调度观察。配置解析器的断言通过，也不意味着上表的自然语言行为已全部实测。

## 真实联动应记录的证据

需要在用户授权的测试任务中确认：主控身份、配置 revision、冻结名单、实际创建设置、各阶段 Agent ID、P/AC/M/C、完成通知、审查原报告、验证结果与交付终点。

至少覆盖简单合作、仅交付两人审查，以及用户明确要求的三人完整审查。先确认 Paseo 已支持所选 Provider/模型；不为验证解析器而调用收费模型。两种主控各开新会话，确认默认值选择；执行中改全局配置，确认本任务未跟着换人。

首轮独立、交叉质疑、修复和批准同一版本，需要会话证据。仅阅读官方代码或模拟配置不能称为完成真实 Claude/Codex/DeepSeek 联动。

已授权本地合并时，再确认所有自动发布入口遵守相同锁协议；锁文件存在不代表这一点已落实。优化效果比较同类任务的总耗时、阶段耗时、模型费用、修复轮次和后续返工，不预先承诺固定节省比例。

2026-10-24 的本地实际任务已观察到 Codex 主控按配置派出一个 Developer，以及 Codex QA、DeepSeek 两个新交付审查会话；两人批准同一候选后，经用户另行授权完成持锁快进和回归检查。此记录支持正常双审路径，不覆盖三人方案审查、实质分歧修复或主控切换等全部场景。本次交接与证据约定的精简仍需后续同类任务验证耗时和 token 变化，自动检查通过不代表已经证明节省。
